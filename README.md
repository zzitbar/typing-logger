# 微博热搜（TypingLog）

表面上是一个微博热搜 App：打开就是热搜榜，右下角有个几乎看不见的小圆点，点它输入密码才进入真正的日志页。

- 不需要 root，不需要电脑。
- 记录由系统无障碍服务完成，界面关掉、进程回收都继续记。
- 日志页要密码（默认 `ZHHL@91xxkj`，可改）；首页不需要密码。
- 可选把每条记录实时推到飞书群机器人。

## 功能

| 功能 | 说明 |
|---|---|
| 微博热搜首页 | 打开即拉取微博公开热搜榜，显示排名、热度，点击条目复制标题 |
| 隐藏入口 | 右下角 44dp 的半透明小圆点，点开输密码进日志页 |
| 记录上屏文字 | 微信、短信、备忘录、浏览器等大多数输入框，带时间与应用名 |
| 飞书推送 | 每条新记录实时推到飞书群自定义机器人，支持签名校验 |
| 本地导出 | 打包成 zip，通过系统分享保存或传走 |
| 暂停/清空 | 记录开关随时暂停；一键清空本机记录 |

## 使用

**首页**：打开就是「微博热搜」，右上角“刷新”手动更新，顶部的“更新于/缓存”表示数据时间；点击某条热搜会把标题复制到剪贴板。

**进日志页**：点右下角那个很淡的小圆点 → 输入密码（默认 `ZHHL@91xxkj`）→ 进入日志页。日志页里是无障碍状态、记录开关、今天的记录、导出、清空、飞书配置、修改密码。

> 小圆点只有 3% 的黑色，正常看不出来，记住位置：屏幕右下角，距边 16dp。

**退出日志页**：按返回或点密码框的“退出”。记录仍在后台继续。

## 被划掉、被杀掉还会记录吗

记录不依赖界面，跑在系统托管的无障碍服务里：

| 场景 | 结果 |
|---|---|
| 从最近任务划掉、系统内存回收 | **会继续记**。系统会重新绑定服务；最多丢最后不到 1 秒、还没落盘的一段。 |
| 设置里“强行停止”、手机管家强制清理 | **不会自动恢复**。需要重新打开一次 App；必要时把无障碍开关关掉再打开。 |
| 重启手机 | 会自动恢复（前提是之前没被强行停止）。 |
| 华为省电策略 | 可能延迟拉起甚至反复杀。加入电池优化白名单、启动管理设为手动可改善。 |

已做的加固：记录**同步落盘**（写完才返回），并在屏幕熄灭、内存紧张、任务被移除时强制把待写的一段写掉。

例外：进程被杀时，已写进本地日志的记录不丢，但**还在内存队列里、尚未发出的飞书消息会丢**，重开不补发。

## 原理与边界

输入法把文字提交给输入框时，输入框发出 `TYPE_VIEW_TEXT_CHANGED`，事件里带变化后的完整文本。应用监听该事件，按“应用 + 窗口”聚合，停顿 800ms 或输入框被清空（发送/切走）时落一条记录；开启推送时同一条记录再发往飞书。

| 能记录 | 记录不到 |
|---|---|
| 最终上屏的汉字/英文、时间、所属应用 | 拼音串、候选词、选了第几个候选 |
| 发送瞬间的整段文字 | 被删掉的中间过程 |
| 微信、短信、备忘录、浏览器等大多数输入框 | 密码框、银行类安全键盘、游戏/Canvas 自绘界面 |

个别输入框会在打拼音的过程中把 `nihao` 这种临时串也报上来；两次停顿超过 800ms 时可能多一条拼音记录，属正常现象。

## 构建

环境：Android Studio Hedgehog (2023.1.1) 或更新，JDK 17，Android SDK 34。

1. Android Studio → **Open**，选择 `typing-logger` 目录。
2. 等 Gradle sync 完成（首次下载 Gradle 8.2、AGP 8.2.2、Kotlin 1.9.22、androidx.core）。
3. **Build → Build Bundle(s)/APK(s) → Build APK(s)**，产物在 `app/build/outputs/apk/debug/app-debug.apk`。

命令行（需本机 Gradle 8.2+ 与 SDK 34）：

```bash
cd typing-logger
gradle assembleDebug
```

## 安装与授权

1. **先退出纯净模式**：设置 → 系统和更新 → 纯净模式 → 退出（需要华为账号密码），否则会拦截非应用市场安装包。
2. 安装 `app-debug.apk`；提示“未经检测”时选继续安装。
3. 打开「微博热搜」，会看到热搜榜首页。
4. 点右下角小圆点 → 输入默认密码 `ZHHL@91xxkj` → 日志页 → **去开启无障碍服务** → 在“已下载的服务”里找到「微博热搜」→ 开启 → 允许。Android 13 及以上若提示“受限设置”，到 应用信息 → 右上角 → 允许受限设置。
5. 回到 App，日志页状态应显示“已开启 ✓”。

建议把「微博热搜」加入电池优化白名单（设置 → 应用和服务 → 应用启动管理 → 手动管理，允许后台活动）。

## 飞书推送配置

1. 飞书群 → 群设置 → **群机器人** → 添加机器人 → **自定义机器人**。
2. 复制它给出的 **Webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）。
3. 安全设置选了 **签名校验** 就把 Secret 一并复制；选了“自定义关键词”则关键词填 `数据记录`。
4. 日志页里：粘贴 Webhook、Secret → **保存** → 打开“检测到新记录就推到飞书” → **测试推送** 验证。

推送内容示例：

```
【数据记录】10-29 09:12:33 · 微信
晚上七点老地方见
```

后台串行、限速 1 秒 1 条，队列最多 200 条，满了丢最旧的，不卡输入。飞书机器人本身约 100 条/分钟，高频时消息排队陆续到达，不丢字。

## 密码

- 默认密码：`ZHHL@91xxkj`
- 修改：日志页最下方 **修改密码**，需原密码，新密码至少 4 位。
- 只保存 SHA-256，不存明文。
- 忘记密码只能清除应用数据（会丢记录）。
- 首页不需要密码；日志页退到后台超过 60 秒再回来要重新输入。

## 隐私

- 首页会访问微博的公开热搜接口（不登录、不上传任何本机信息），并缓存最近一次结果用于断网展示。
- 日志页默认不联网；开启飞书推送后，记录会发到你填的 Webhook。
- 记录保存在 `/data/data/dev.local.typinglog/files/logs/`，卸载即清除。
- 日志页禁止截屏、最近任务预览显示为空白；需要带走内容请用“导出”。
- 只适合记录**你自己的**输入；如果别人也用这台手机，请先告知。

## 常见问题

**热搜加载失败？**
微博接口偶尔限流或改版，页面会显示上次缓存。点“刷新”重试；长时间失败说明接口变了，需要更新 `HotSearchRepository.kt` 里的地址或解析逻辑。

**找不到日志入口？**
右下角距边 16dp 处有个 3% 黑的小圆点，正常看几乎不可见。

**测试推送失败？**
看日志页“推送状态”：`HTTP 4xx` 多半是 Webhook 抄错或机器人被移除；`sign match fail` 是 Secret 不对；关键词不匹配就把群里关键词改成 `数据记录`。

**开了无障碍但没记录？**
确认状态显示“已开启 ✓”，在微信里打几个字等 1 秒。部分 App 自绘输入框不发文本变化事件，换个 App 试试。

**想要更完整的记录（含拼音、候选、删除）？**
只能在输入法进程里做，需要 root + LSPosed 钩 `BaseInputConnection#commitText`，或换一个自己改过的输入法（如同文输入法 Trime）。Pura 70 没有官方解锁 BL 的途径，root 这条路基本走不通。
